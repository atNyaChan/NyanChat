# Nyanw 版本改动记录

## Agent 协作约定
- `AGENTS.md` 要求 Agent 在每次代码、资源或配置修改后同步维护本文件。
- 编辑本文件前先从头到尾阅读一次，不要只是往最后添加信息，也不要只使用 grep 简略阅读。
- 修改完成后要静态检查本次改动涉及的未引用组件，并删除未引用的翻译资源字符串，并使得各翻译资源与英文源文件同步。
- 禁止 Agent 自行执行编译、构建、测试或 Lint；相关验证由维护者手动完成。

## 聊天与消息
### 词数及生成统计（开启“显示 Token 数等统计信息”时）
- 相邻 ASCII 英文字母合计为一个词；其他 ASCII 符号、空格、CJK 字符和 emoji 等每个 Unicode 码点各计一个词。
- 用户消息的操作按钮行左侧显示词数。
- 流式回复期间每 100ms 更新词数（包含正文和思考过程）、已用时间、词/秒及生成中的思考词数。
- 生成完成后助手统计变为两行：第一行显示词数、时间、词/秒，第二行显示输入（缓存 token）、输出、token/秒（及费用（如果设置了模型单价））。
- 消息用时不足 150ms 时不显示 `word/s` 和 `tok/s`，避免展示失真的瞬时速度。
- 点击统计只切换精确数字和 `12.3K` 一类的缩写；仅数量超过 `10000` 时才采用缩写，并且无论数量多大都只使用 `K`。
- 模型 id 为空的助手消息（即为手动编辑的消息）只显示词数，并标注` (edited)`。
- 手动编辑的消息中的思考块只显示“思考”，自然生成且带有用量信息的零耗时思考仍显示“思考了 0.0 秒”。

- 输入框加号左侧分两行显示{当前输入词数、下一次请求总词数（不计思考内容）}、{附件与可供模型使用的工具数量（含内置工具）}；第二行按实际存在的项目显示文件、工具图标及数量，两行右对齐并整体垂直居中。
- 编辑历史消息时输入框统计只覆盖被编辑消息及其之前的内容。
- 输入框中的可解析文本文件会在附件框外侧右边显示文件正文词数，计入下一次请求总词数，不计入附件数；当前输入词数只统计直接输入的文本，不重复计算附件词数。
- 输入框获得焦点时构建并缓存系统提示、记忆、工具提示及转换后的既有历史消息；显示的总词数直接为缓存上下文词数加当前草稿词数。
- 开启“收起输入框工具栏”时，输入框为空或工具栏收起（键盘展开）时跳过下一次请求总词数与工具数的统计（不只是隐藏显示），恢复输入或工具栏展开后再重新统计。
- 点击输入框旁的加号打开面板修改设置会实时刷新上下文统计值。
- 用户消息中的可解析文本文件左侧显示灰色文件正文词数；只统计解析出的正文，不包含文件名及请求转换时加入的上传文件标签或包装文字。
- 键盘未弹出且没有草稿或附件时隐藏统计；展开加号面板时仍显示统计。
- 统计数值沿用消息统计的 `K` 缩写规则；关闭“显示 Token 数等统计信息”设置时不显示也不计算。
- 用户消息时间位于词数统计左侧（关闭统计时仍占据该位置），用户与助手消息时间均沿用词数统计颜色；今天和昨天的消息分别以“今天”或“昨天”代替日期，其余日期使用 `yyyy/MM/dd`，后面均保留 `HH:mm` 时间。

### 思考块
- 编辑助手消息时，将 `Reasoning` 内容重新插入输入框并表示为 `<think>...</think>`。
- 保存编辑后的助手消息时，将 `<think>` 标签重新解析为独立思考块。支持一条编辑文本中出现多个 `<think>` 块。
- 新增设置“解析中途思考”（默认：开启），开启时消息开头以外的 `<think>` 标签也会被解析为思考块，流式生成与手动编辑消息均受此开关影响。
- 思考完成并展开思考块后，顶部右侧显示思考词数和复制按钮（点击即可复制思考 Markdown 原文）。
- 展开或收起思考与工具步骤时，标题行的按压反馈左右各保留 4dp 空白。
- 设置里的“生成时显示思考”可以选“收起”、“预览”和“展开”。思考中点击思考块标题即可在收起与展开（设置值=“收起”）或预览与展开（设置值=“预览/展开”）之间切换。
- 渲染思考块时去掉思考块结尾的换行，避免末尾残留多余空行。
- 缩短思考块内文字与思考块下边缘的间距。

### 空白消息
- 允许发送仅包含空格等空白字符的消息。
- 同步调整了输入校验、消息 UI 判断及发送给模型前的消息过滤。
- 真正的空字符串仍不能作为单独消息发送。
- 纯空白用户消息使用不可见占位符维持正常气泡行高；该占位符仅用于显示，不改变保存或发送的原始内容。
- API 生成流正常结束且实际收到助手响应事件、其回复长度确实为 0 时保留空助手消息。

### 模型价格
- 每个提供商的每个模型均可选中“设置价格”。
- 支持填写输入、输出、缓存读取、缓存写入价格，单位为美元/百万 token（输入/输出一行、缓存读取/写入一行）。
- 价格设置默认关闭，旧模型数据因字段具有默认值而保持兼容。
- 未出现缓存读取时，费用计算为 `输入价格 × 输入 token + 输出价格 × 输出 token`。
- 出现缓存读取时，不使用普通输入价格，费用计算为：
	```text
	缓存写入价格 ×（输入 token - 缓存读取 token）
	+ 缓存读取价格 × 缓存读取 token
	+ 输出价格 × 输出 token
	```
- 开启模型价格设置后，在四个价格输入框下方直接显示无缓存读取与有缓存读取两种计算公式。

### 侧栏
#### 搜索消息
- 搜索聊天页共有“仅匹配标题”、“精准匹配”、“模糊搜索”、“按照模型…”、“按照附件…”五种模式；默认使用精准匹配并记住用户选择（只有前三种可以被用作默认值）。精准匹配使用区分大小写的连续字符串包含判断；模糊搜索按空格拆分关键词，要求各段在消息中依次且全部出现，例如 `你 好` 可匹配“你真好”，`s r h` 可匹配 `search`。仅模糊搜索允许按相关性排序，其他搜索模式及模型筛选会自动改为从新到旧，新安装默认从新到旧。
- 模糊搜索选择并高亮消息中 各空格分段按顺序出现且间隔字符总数最少的一组完整匹配；按相关性排序时优先显示总间隔更少的结果，相同则按消息时间从新到旧。
- 预览从首段所在行延伸到末段所在行，匹配相隔较远时自动包含中间全部行。
- 新版搜索统一读写独立的普通表 `message_search_cache`，不扫描消息 JSON，并移除 Jieba 查询与词典资源。旧名 `message_fts` 保留为空的 `simple` FTS5 兼容表，旧版会忽略新缓存表，导回旧版后可手动重建旧索引。
- 消息搜索缓存写入完整文本，不再将每条消息截断到 10,000 字。
- 新版打开数据库时若发现旧表存在条目，会先清空旧表，再与页面手动重建共用同一实现，从原始会话及消息记录全量重建新缓存，两个缓存表的旧内容都不会作为重建来源。
- “按照模型…”内提供“现有的模型”、“已被删除的模型”、“手动编辑的消息”三个选项。
- “按照附件…”可分别查找附件仍存在或本地附件已被删除的消息。
- 侧栏入口与搜索页标题统一复用“搜索消息”文案。
- 消息搜索在标题同一行显示“xx个结果”。
- 搜索结果改为每页 20 条，超过一页时在搜索框下方提供首页、上一页、页码输入、下一页和末页控件。
- 重建搜索索引时清空页面内容，仅保留标题栏及右上角按钮，并在内容区域中央显示圆形加载指示器。

- 导入完整备份后扫描消息数据库，将图片、文档、视频和音频记录中的旧绝对 `file:` 路径按文件名统一改写为当前安装 `upload` 目录下的标准 `file:///…` 路径；本地、WebDAV 和 S3 恢复共用同一重写实现。
- 新导出格式改为 `.tar`，文件命名为 `NyanChatBackup-yyyyMMdd-HHmmss.tar`：
	- 导出前对 SQLite WAL 执行 checkpoint，变为单个 `.db` 文件。
	- 数据库只导出一个 `rikka_hub.db.zst`，不再携带 `-wal` 和 `-shm`，并使用 zstd 等级 9 多线程压缩，再与 `settings.json`、`upload`、skills、fonts 等附件一起打入 tar。
	- 选择导出“文件”时，在 `workspaces/` 下为所有非 `DISABLED` 工作区按根标识生成独立的 `{workspaceRoot}.tar.zst`；每个子归档复用单工作区导出实现，包含 Rootfs 及对应 `/workspace` 文件。恢复时会将两部分还原到对应工作区。
	- 本地、WebDAV 和 S3 使用相同的新格式。
- 导入根据文件后缀识别新 `.tar` 与旧 `.zip`，旧 ZIP 备份仍可还原。
- 本地导出额外提供旧 ZIP 兼容格式（移除 Fork 新增的模型价格、排序、显示、上下文缓存与本地工具授权字段，并过滤官方版本无法反序列化的电池和定位本地工具，并标注“兼容 RikkaHub 2.4.x”）；该兼容 ZIP 不包含工作区环境，S3 与 WebDAV 仍只导出新的 TAR 格式。
- Android 端 zstd 使用官方 `zstd-jni` AAR（包含各 Android ABI 原生库），避免普通 JVM JAR 缺少 `.so` 导致导出失败；Release 混淆配置保留 zstd-jni 的 JNI 字段与方法名，避免导出时因字段被重命名而报 `dstPos` 缺失。
- 完整恢复前关闭 Room 数据库并清理目标数据库的旧 WAL/SHM，避免旧连接覆盖刚恢复的对话数据。
- 通过本地文件、WebDAV 或 S3 导入新 TAR 存档时会恢复工作区环境；导入不包含工作区环境的兼容 ZIP 时，才由 ZIP 专属的恢复实现将所有工作区状态重置为 `DISABLED`。
- 本地导入与导出的失败提示分别显示为“导入失败”和“导出失败”。
- 备份导入导出期间显示不可通过返回键关闭的横向直线进度条对话框，备份页导入项目不再显示加载动画。

### 请求日志

- 日志详情、请求/响应 headers 默认折叠，字号统一为 12sp（行高 16sp）。
- 日志只展示文本响应；gzip、deflate、Brotli 和 zstd 编码的文本先解压。
- 请求日志入口说明日志仅覆盖本次应用启动期间。
- 右上角在删除图标左侧新增筛选键，可选“全部”、“仅 LLM 调用”、“非 LLM 调用”，筛选状态仅本次应用启动期间有效，与应用日志内容一样不做持久化。
- 在 LLM 请求中显示 `Model: {xxx}`（位于 `Status:` 之前），`Model:` 用普通颜色，模型名用等宽加粗字体并使用主色高亮。
- `Status:` 改为普通颜色，仅状态码使用等宽字体并保留原有高亮色。
- 请求日志页右上角筛选、条目中的模型名显示、详情页 Content 三处是否 LLM 请求的判断统一收敛到 `isLlmRequest(log)`。
- 设置页新增“权限请求日志”，记录剪贴板、电池电量、位置信息、屏幕时间、日历等工具的请求类型、工具代码名、时间及完整原始数据和返回结果，用与 HTTP 日志一致的可折叠 JSON 高亮树显示，但节点默认全部展开。权限日志与聊天默认工具调用复用同一详情内容并按内容自然确定底部抽屉高度。
- 网络请求日志页顶部（标题下方）新增“【调试】实时显示发送的请求”卡片（描述“在发送网络请求前弹出确认弹窗”）下拉框（关闭/仅 LLM 请求/全部），开关状态仅本次应用启动期间有效（重启恢复为“关闭”）。开启后，发出作用范围内的请求前会弹出确认弹窗：标题为“【调试】即将发送的网络请求：”，最前面显示 `[{METHOD}]: {URL}`（例如 `[POST]: https://...`），下方 Request Headers 与 Request Body 复用日志详情页同款的可折叠节（Body 默认展开，其 JSON 树顶层展开显示 `{}` 内第一级内容，无 Body 则不显示该节）；底部两侧为“取消发送”与“确认发送”，取消发送时抛出与真正断网同款的 `ConnectException`。是否 LLM 请求沿用与日志筛选一致的 `isLlmRequest` 判断。
- 每发一次请求、收到回复后立即记一行请求日志，不再等流式正文读完或全部重试完成才出现。收到响应头/状态码后立刻创建条目，正文读取完成后再原地更新同一条目（补上响应正文、最终耗时与错误）。每次网络重试（如自动重试 3 次）都会在重试过程中实时产生对应条目。
- 网络请求日志页列表改为实时刷新（每 500ms 轮询 `Logging.getRequestLogs()`），页面上即可看到重试过程中每行请求依次出现。
