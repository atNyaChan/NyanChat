# Nyanw 版本改动记录

## Agent 协作约定

- 仓库级 `AGENTS.md` 新增 Agent 收尾流程：每次代码、资源或配置修改后同步维护本文件。
- 编辑本文件前先从头到尾阅读一次，不要只是往最后添加信息。
- 修改完成后要静态检查本次改动涉及的未引用组件及 locale/string 资源并清理。
- 每次修改后都需要删除未引用的翻译资源字符串，并使得各翻译资源与英文源文件同步。
- 禁止 Agent 自行执行编译、构建、测试或 Lint；相关验证由维护者手动完成。

## 聊天与消息

### 助手切换

- 修复切换助手后，在空白聊天页发送的第一条消息偶尔被写入上一个助手的问题。
- 修复方式为在创建新会话时明确使用当前助手，避免异步状态更新期间读取到旧助手。
- 该问题触发概率较低，仍需在日常使用中继续观察。

### 词数及生成统计

- 用户消息的操作按钮行左侧显示词数；助手消息词数包含正文和思考过程。
- 相邻 ASCII 英文字母合计为一个词；其他 ASCII 符号、空格、CJK 字符和 emoji 等每个 Unicode 码点各计一个词。
- 流式回复期间每 100ms 更新词数、已用时间、词/秒及生成中的思考词数。
- 生成完成后助手统计变为两行：第一行显示词数、时间、词/秒，第二行显示输入（缓存 token）、输出、token/秒及可能的费用。
- 点击统计只切换精确数字和 `12.3K` 一类的缩写；仅数量超过 `10000` 时才采用缩写，并且无论数量多大都只使用 `K`。
- 用户消息和思考块的词数统计使用同样的浅灰色样式、`word` 单位及缩写规则。
- 手动编辑且没有生成用量的助手消息只显示词数。
- 已结束且没有生成用量的助手消息按手动编辑消息处理；其中的零耗时思考块只显示“思考”，自然生成且带有用量信息的零耗时思考仍显示“思考了 0.0 秒”。
- 手动编辑消息统一以模型 ID 是否为空判断。
- 消息用时不足 150ms 时不显示 `word/s` 和 `tok/s`，避免展示失真的瞬时速度。

### 思考

- 编辑助手消息时，将 `Reasoning` 内容重新插入输入框并表示为 `<think>...</think>`。
- 保存编辑后的助手消息时，将 `<think>` 标签重新解析为独立思考块。
- 支持一条编辑文本中出现多个 `<think>` 块。
- 思考块与正文之间不再自动插入新的换行，避免反复编辑后继续累积。
- 增加“复制思考过程”按钮，复制内容为 Markdown 原文。
- 思考完成并展开思考块后，顶部显示思考词数和复制按钮。

### 空白消息

- 允许发送仅包含空格等空白字符的消息。
- 同步调整了输入校验、消息 UI 判断及发送给模型前的消息过滤。
- 真正的空字符串仍不能作为单独消息发送。
- 纯空白用户消息使用不可见占位符维持正常气泡行高；该占位符仅用于显示，不改变保存或发送的原始内容。

### 模型价格

- 每个提供商的每个模型均可选中“设置价格”。
- 支持填写以下价格，单位为美元/百万 token：
  - 输入
  - 输出
  - 缓存读取
  - 缓存写入
- 输入/输出一行、缓存读取/写入一行。
- 价格设置默认关闭，旧模型数据因字段具有默认值而保持兼容。
- 未出现缓存读取时，费用计算为输入价格 × 输入 token + 输出价格 × 输出 token

- 出现缓存读取时，不使用普通输入价格，费用计算为：

  ```text
  缓存写入价格 ×（输入 token - 缓存读取 token）
  + 缓存读取价格 × 缓存读取 token
  + 输出价格 × 输出 token
  ```

- 最终结果除以 `1,000,000`，并显示在助手消息统计末尾。

### 侧栏

#### 搜索消息

- 搜索聊天页增加“仅匹配标题”、“精准匹配”、“模糊搜索”三种模式；默认使用精准匹配并记住用户选择。精准匹配使用区分大小写的连续字符串包含判断，模糊搜索保留原 FTS/Jieba 实现。以及新增“搜索模型…”，提供“现有的模型”“已被删除的模型”“手动编辑的消息”三个选项（不会覆盖默认搜索方式）。

- 消息搜索改为每页 20 条，超过一页时在搜索框下方提供首页、上一页、页码输入、下一页和末页控件。
- 搜索结果数移动到“搜索消息”标题右侧并按文字下边缘对齐；仅模糊搜索允许按相关性排序，其他搜索模式及模型筛选会自动改为从新到旧，新安装默认从新到旧。
- “重建消息索引”更名为“重建模糊搜索索引”，“通用设置”说明更新为“界面、主题、聊天交互等常规设置”。

### 备份与恢复

- 数据设置中的入口名称改为“备份与恢复”。
- 描述改为“备份或覆盖还原整个RikkaHub”。
- “聊天记录存储”改为“聊天文件存储”。
- 本地、WebDAV、S3 的覆盖还原操作均增加确认弹窗。用户必须在提示现有配置和数据会被覆盖后点击“好”，才会进入文件选择或开始还原。
- ChatBox、Cherry Studio 等合并式导入不属于覆盖还原，因此不显示覆盖警告。
- 本地完整备份和还原固定包含数据库与文件，不再受 WebDAV 备份项目勾选状态影响。
- 导入完整备份后扫描消息数据库，将图片记录中的旧绝对 `file://` 路径按文件名改写为当前安装 `upload` 目录的路径。
- 新导出格式改为 `.tar`：
  - 导出前对 SQLite WAL 执行 checkpoint，归并到主数据库。
  - 数据库只导出一个 `rikka_hub.db.zst`，不再携带 `-wal` 和 `-shm`。
  - 数据库使用 zstd 等级 9 压缩，再与 `settings.json`、`upload`、skills、fonts 等附件一起打入 tar。
  - 本地、WebDAV 和 S3 使用相同的新格式。
- 导入根据文件后缀识别新 `.tar` 与旧 `.zip`，旧 ZIP 备份仍可还原。
- 本地导出额外提供旧 ZIP 兼容格式；S3 与 WebDAV 仍只导出新的 TAR 格式。
- Android 端 zstd 使用官方 `zstd-jni` AAR（包含各 Android ABI 原生库），避免普通 JVM JAR 缺少 `.so` 导致导出失败。
- Release 混淆配置保留 zstd-jni 的 JNI 字段与方法名，避免导出时因字段被重命名而报 `dstPos` 缺失。
- 本地导入与导出的失败提示分开显示为“导入失败”和“导出失败”。
- 完整恢复前关闭 Room 数据库并清理目标数据库的旧 WAL/SHM，避免旧连接覆盖刚恢复的对话数据。
- 备份页签顺序调整为本地、S3、WebDAV、提醒。
- 设置页的备份说明注明“不包含工作区环境”。
- 导出本地、WebDAV 或 S3 备份前先写入最新备份时间，使归档内的设置也包含该时间；导出或上传失败时恢复导出前的时间。
- 备份进行期间会锁定备份页返回操作。
- 本地及第三方导入时显示不可通过返回键关闭的“正在导入”对话框，框内使用横向直线进度条，完成后同一对话框切换为重启提示；备份页导入项目不再显示进度动画，页面也不额外锁定返回键。
- “导入本地备份文件”说明明确仅支持 NyanChat 和 RikkaHub 2.x。

### Web 服务器

- 地址区域只保留一个“网址”项目。
- 展示手机当前可用的全部局域网 IPv4 地址，每行一个。
- 不显示 `localhost`、`127.0.0.1` 或 IPv6 地址。
- 复制网址功能会复制当前展示的有效地址。
- Web 服务器启动后注册 mDNS，可通过对应的 `.local` 地址访问。
- 端口和密码输入框字号适当缩小，并使用正常字重，避免视觉上过大或过粗。

### 请求日志

- 永久启用记录请求日志，并更名为“网络请求日志”。
- 请求和对应响应合并为同一个条目，记录双方 headers、正文、HTTP 状态和耗时。
- 请求失败只记录单行错误摘要，不在请求日志页显示 Java 日志或异常堆栈。
- 无请求记录时在页面中央显示灰色空状态提示。
- 请求/响应 headers 与正文均提供一键复制；JSON 和 SSE 中的 JSON 数据支持树形高亮与折叠，且默认从根节点折叠，点击根节点后再展开完整内容。
- 仅对识别出的 LLM 响应显示 Content，并按流事件顺序将思考、正文和工具内容分别显示在只读文本框中，每个文本框提供独立复制按钮。
- 日志详情、请求/响应 headers 和 body 默认折叠，仅完整响应 Content 默认展开，字号统一为 12sp（行高 16sp）。
- 日志只展示文本响应；gzip、deflate、Brotli 和 zstd 编码的文本先解压。
- 流式响应在结束标记或 EOF 前被手动中断时，保留 HTTP 状态、响应头和已接收正文，并额外记录单行错误“流式响应已中断”；正常结束后的内部取消不报错。
- 设置页新增“权限请求日志”，记录系统权限、使用时间、剪贴板和日历等工具的请求类型、时间及完整原始数据和返回结果，用与 HTTP 日志一致的可折叠 JSON 高亮树和字体样式，区块及 JSON 节点默认全部展开。
- 请求日志入口说明日志仅覆盖本次应用启动期间。

## 其它
